# Design

## System

- A compact desktop editor with full-bleed canvas and floating chrome; drawers overlay the stage rather than resize it.
- The design system is coss ui (Base UI), installed by the shadcn CLI from the `@coss` registry into `src/components/ui/` and never edited by hand — `pnpm run audit:ui` fails naming the file the moment its content drifts from the registry. Project-specific composition (an `Island`, a `PropertyRow`, a colour swatch — anything coss has no primitive for) lives in `src/components/patterns/` instead.
- Dark is the default theme with a complete light override; coss's own convention (bare `:root` is light, `.dark` overrides) replaced the earlier `.light`-class scheme.

## Tokens

- `src/index.css` follows the shadcn token contract, filled by coss's own neutral palette (`@coss/colors-neutral`, chroma 0) rather than a hand-picked ramp; only sixteen tokens sit outside it, for concepts shadcn has no name for, plus six named z-levels — declared in `src/design-system/tokens.css`, the project's one extension layer, alongside `motion.css` (durations, easings, the single reduced-motion block) and `stage.css` (stage grain, marker utilities, squircle).
- Chrome surfaces are achromatic so they do not distort color judgment on the artboard. The stage carries a dot grain rather than a flat fill, from a token that lightens on dark and darkens on light; being decorative it is deliberately excluded from the contrast matrix.
- Layer geometry is written in scene coordinates through a single function, which places via the parent's plane whenever the object is inside a multi-selection. Fabric re-parents objects into an active selection, so an absolute write during a sync moves them off their artboard without anything in the project having changed, and the wrong position becomes real on the next modification.
- On the board, the current screen is the one that floats, never the one wearing a ring. The artboard stroke is uniform and structural — it says where a near-white board ends on a near-white stage — because a stroke lives on the board's edge, under the layers, and any content reaching that edge painted over it. State moves to the shadow beneath the board and to the label above it, both outside the artwork and both achromatic. A single function returns that appearance, since the sync pass and the theme pass both apply it.
- The light theme runs on two levels rather than a five-step ramp: a near-white stage, white islands, and the elevation tokens doing the separating. A lighter stage gives a shadow more room to bite than a grey one did.
- Lime lives under `--color-marker`, reserved for location/state and focus; `accent` keeps its shadcn meaning of neutral hover surface. Primary actions use neutral fills, while red is reserved for destructive state.
- The rendered scales follow coss's own type, height and radius steps rather than a bespoke chain, and stay closed by measurement: `pnpm run audit:scale` counts the values actually rendered in the populated DOM instead of comparing against a hand-kept whitelist, since a literal size in a utility class no longer shows up in `index.css` for a static check to read. The radius chain derives from one upstream value (`--radius: 0.625rem`) by fixed offsets — `sm` 6px, `md` 8px, `lg` 10px (buttons, inputs), `xl` 14px, `2xl` 18px (islands, popovers, modals).
- Line-height is declared in px on a grid, not a ratio, but the discipline now comes from coss's own type scale (each rendered size already pairs with a fixed pixel line-height) rather than from a local override stripping Tailwind's ratio-named utilities; the scale guard still measures computed line-height directly and rejects any rendered value off the 4px baseline regardless of how it got there.
- Canvas geometry shared with floating chrome lives in `src/lib/stage.ts`. The floating surface itself is a component (`Island`, wrapping coss's `Card` anatomy with a fixed padding) rather than a CSS class with a derived inset — the earlier concentric-radius formula is gone with the class it belonged to. The filmstrip is not an island: its padding is the clearance its scroll box owes a tile's focus ring, since `overflow-x: auto` forces the vertical axis too. It pins the vertical axis hidden and reserves a fixed height for the horizontal bar, which stays visible — on a narrow window that bar is what says more screens exist to the right.
- The same file derives the responsive thresholds: one drawer at a time, then a folded overflow menu in the top bar, then the creation tools folding into it, then a filmstrip that stops being centred. The editor is desktop-class but renders at any width instead of refusing; what it protects is that no control leaves the viewport and nothing floating steals a neighbour's click. Below roughly 600px a drawer covers nearly the whole stage, which is the stated trade.

## Components

- Commercial surfaces present exactly two offers: free Local and paid Cloud. Cloud is standalone and its account state names projects, images and settings sync explicitly; no trial, export paywall or Local purchase is presented.
- Controls compose coss's own primitives (`Button`, `Input`, `NumberField`, `Select`, `Slider`, `Switch`, `Dialog`, `Popover`, `Menu`…) directly from `components/ui/`, or a shared pattern from `components/patterns/` (`IconButton`, `PropertyRow`, `UnitField`, `Segmented`, `SwatchButton`…) when coss has no equivalent. A pattern composes coss primitives; it is never a hand-rolled control.
- Project navigation uses a dedicated `ProjectSwitcher`: the current project and its actions form the first section, while a read-only, filterable catalogue lists every other local project by freshness. Availability describes the copy, not the commercial offer: `Cet appareil` means no Cloud acknowledgement for the active account, `Cloud` means its current version is acknowledged, and `À synchroniser` means the local version is newer. Without an active Cloud entitlement, every project is described as `Cet appareil`.
- Project setup chooses an immutable App Store iPhone or Google Play phone destination before the first board exists. The active target badge is informational, never an export-time switch; device and template pickers show only compatible assets.
- The first-Cloud-login dialog is a consent boundary, not an editor: its semantic `Projets à ajouter` list is visually flat and never changes names. `Pas maintenant` uploads nothing; the quantity-aware primary action explicitly adds exactly the listed projects to Cloud, and every outcome preserves the local copies.
- Single-line controls carry inline labels; only composite or multiline controls stack labels, sliders included when nothing else names them.
- Panel sections are hairline-separated bands, so no chrome stacks more than two surfaces; recessed cards remain a modal device.
- Layer rows show a text layer's own content until it is renamed, and the filter searches what the rows display.
- Filmstrip tiles are sized from the active target's real ratio (440×956 Apple or 540×960 Android), so previews never imply the wrong framing. Widening a tile means raising its height and letting the width follow. Every screen always has a name (`defaultScreenName(index)` until renamed), so the badge and label rows are reserved permanently: `filmstripHeight()` takes no argument, the strip costs the canvas a fixed height once, and the stage never jumps when a screen is named.
- The filmstrip carries no surface of its own; the previews are the surfaces and a container around them would stack three neighbouring lightnesses. Each tile is a single button, and nothing of the interface is laid on the preview: the number badge sits in its own row above the image — on the preview it cost a corner of every composition in the one tool whose job is to show those compositions — and takes the theme's own tokens (`marker-fill` when current, `muted-foreground` otherwise; the old `black/60` literal is gone). The current screen is the one whose badge turns lime, rises out of the row and carries the strip's only contact shadow; a ring is never used for state, and under reduced motion the rise drops while the badge and shadow keep carrying it. Island elevation is the wrong scale for a tile that small — its low layer reached far below the tile and the horizontal scroll box, which clips both axes, cut it flat. A shadow the container cannot show whole is worse than none. Previews are captured at twice the tile's own size rather than at a fraction of the artboard, with the canvas's control drawing suppressed so the selection frame is not baked in, and they carry no image outline of their own since the tile's border already frames them. Reordering is previewed during the drag itself: the row parts by one slot and the dragged tile hides, so the strip shows its post-drop shape rather than only reflowing after the release. A single lime bar fills the vacated slot, since the shift states the final arrangement while the bar states the insertion point, and the two read differently at the strip's edge; it is the one transient exception to the marker appearing once, and it stays inert to the pointer so it cannot intercept the drag events that pick its own target.
- Dense control heights, tabular numeric values, one primary CTA per dialog, and 120–300ms transform/opacity motion are the default grammar; list enter/exit and success-check animations live on `--animate-*` tokens (120–300ms, one spring-like `linear()` settle for entrances), all neutralised into fades by `prefers-reduced-motion`. Two blocks carry that fallback — the design-system extension covers its own utilities, and `index.css` covers the coss menu-popup timing it overrides outside coss's own layer — because the second exists only to win a specificity fight the first can't reach.
- Grab handles share a contact-shadow token and a focus-ring token rather than inline shadow literals; they sit outside the island elevation scale because a handle detaches from its surface instead of floating above it. Ink that lands on user content, not on chrome, stays deliberately unthemed.
- Lazy dialogs immediately show a token-based modal loading surface with an announced status; reduced-motion users get the same feedback without animation.
- `index.html` paints a named boot skeleton inside `#root` — React clears the container on mount, so nothing has to remove it. Inter and Geist Mono are self-hosted variable fonts (`@fontsource-variable/*`, imported into `index.css`), which removed the earlier deferred-stylesheet flip entirely rather than moving it. The critical bundle is ~272 kB gzip and mostly Fabric, which a canvas editor needs on first paint; the fix is feedback, not further splitting.
- If durable storage is unavailable, the editor remains usable in memory while the save status and a persistent alert disclose that closing the tab will lose the session.

## Accessibility

- Text/surface contrast must remain at least 4.5:1 and pass `pnpm run audit:contrast`; the rendered scales must pass `pnpm run audit:scale`.
- Icon-only controls require accessible labels; dialogs trap and restore focus; menus, listboxes, switches, alerts, and live status use appropriate roles.
- Heading levels are real elements, not classes: an `sr-only` `<h1>`, `<h2>` panel titles, `<h3>` section titles, and a collapsible section is an `<h3>` wrapping its `aria-expanded` button. The top bar is a `<header>` and each panel an `<aside aria-labelledby>`.
- Keyboard operation and visible focus are baseline behavior. Under `prefers-reduced-motion` only movement is removed: `transform` leaves the transition list and sliding entrances become fades, so state feedback stays visible.
- Chrome density keeps most controls at 32–36px; 44px hit areas are only applied where the extended zone cannot steal a neighbour's click.
