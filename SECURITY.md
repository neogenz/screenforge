# Security policy

## Supported versions

Until the first tagged release, security fixes target `main`. After that,
ScreenForge supports the latest tagged release and `main`; older releases may
require upgrading before a fix is available.

## Reporting a vulnerability

Please use [GitHub private vulnerability reporting](https://github.com/neogenz/screenforge/security/advisories/new).
Do not include credentials, customer data or exploit details in a public issue.

Include the affected version, a minimal reproduction and the expected impact.
The maintainer will acknowledge the report privately, validate it and coordinate
a fix and disclosure when appropriate. ScreenForge is independently maintained,
so no response SLA is guaranteed, but reports are triaged as a priority.

Please allow time for a fix before publishing details. Credit is welcome and
will be included when requested, unless doing so would expose the reporter or
another person.

## Scope

Security reports may cover this repository and the operated ScreenForge Cloud
service. Local-only product questions and feature requests belong in regular
GitHub issues and must not contain sensitive data.
